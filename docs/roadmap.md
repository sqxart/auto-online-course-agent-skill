# Roadmap

## Phase 0 — 技术验证

用用户授权的测试范围验证真实播放、平台完成标记和异常恢复。公开笔记只记录通用技术结论，原始运行证据留在本地。

## Phase 1 — 仓库骨架与知识库

- README、LICENSE、架构文档与匿名技术笔记。
- 双平台 `knowledge/` 与 harness 无关的 `SKILL.md`。
- 保活脚本、只读信标、字体映射辅助工具和续跑模板。

## Phase 2 — Runner 与监督模式

- 中国大学MOOC：自动发现课件矩阵、跳过 learned、自适应登录、真实播放、看门狗和暂停原因协议。
- 学习通：章节发现、假完成防御、日上限/弹题/验证码停止；无头形态仍需收敛，可见浏览器监督作为可用路径。
- 凭据由本次用户交付，通过临时环境或忽略的本地文件传递；登录态和账号资料只留本地。
- 锁速场景接受 1x，用只读信标；按工具调用上限安排检查与等待。
- 字体混淆按页随机，映射降级为页内辅助；用 canvas/OCR 读取题面。
- 重做按结果页能力和现有用户授权处理；精确设定选项集合，保留任务点独立核验。
- 后续从两个 Runner 中提炼真正共享的看门狗、`pauseReason` 与凭据握手，不预先抽象平台差异。

## Phase 3 — 模式配置化

- intervention、cadence、concurrency 旋钮与 safe/token-saver/efficient 预设。
- 多账号独立 profile、状态文件与汇总面板。
- 等待间隔、每日时段窗口和任务量上限配置。

## Phase 4 — 产品线扩展

- 浏览器脚本/插件复用知识库选择器与保活逻辑。
- 新平台增加对应 knowledge 文档与 `SKILL.md` 路由，保留各平台的能力边界。

## Phase 5 — 发布

补足运行说明、依赖与验证，检查公开树和可达 Git 历史的隐私信息。通用改进按用户授权整理为上游 PR，描述技术问题、实现和匿名验证结论。
